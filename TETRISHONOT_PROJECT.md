## ⚠️ ОТКРЫТАЯ ЗАДАЧА: браузер предупреждает о небезопасности

Диагностика 2026-08-03. **Причины две, обе чинятся в веб-интерфейсе GitHub**
(Settings → Pages репозитория `fildrummm-afk/tetrishonot-site`). Сервер и DNS ни при чём.

### Причина 1 — на `www` нет своего сертификата

`https://www.tetrishonot.com` отдаёт сертификат с именем **`*.github.io`** вместо
`www.tetrishonot.com`. Браузер видит, что имя в сертификате не совпадает с адресом,
и показывает предупреждение об угрозе. Редирект 301 на apex настроен и работает,
но TLS-рукопожатие происходит **раньше** редиректа — поэтому предупреждение успевает
выскочить.

```
apex:  subject= CN=tetrishonot.com     ← Let's Encrypt, всё верно
www:   subject= CN=*.github.io          ← ЧУЖОЕ ИМЯ, отсюда предупреждение
```

### Причина 2 — выключен «Enforce HTTPS»

`http://tetrishonot.com` отдаёт **200 вместо 301** — то есть по незашифрованному
протоколу сайт открывается как есть, без переброса на HTTPS. Chrome помечает такие
страницы как «Не защищено».

### Что сделать (веб-интерфейс, ~3 минуты)

1. GitHub → репозиторий `tetrishonot-site` → **Settings → Pages**.
2. В блоке **Custom domain**: нажать **Remove**, сохранить, затем вписать заново
   `tetrishonot.com` и сохранить. Это заставит GitHub перевыпустить сертификаты
   **сразу на оба имени** — apex и www.
3. Дождаться, пока пропадёт надпись про «certificate is being provisioned»
   (обычно 5-20 минут, иногда до часа).
4. Поставить галочку **Enforce HTTPS** — она становится доступной только после
   выпуска сертификата.
5. Проверить оба адреса: `https://www.tetrishonot.com` и `http://tetrishonot.com`
   (второй должен сам перебросить на https).

### Дополнительно: срок сертификата

Текущий сертификат apex выпущен **10.05.2026**, истекает **08.08.2026** — на момент
диагностики оставалось **5 дней**. GitHub Pages обновляет Let's Encrypt автоматически,
но раз перевыпуск всё равно требуется по причине 1, он заодно закроет и этот вопрос.
Если после 08.08 сайт начнёт ругаться на просроченный сертификат — причина здесь.

### Что проверять НЕ надо

DNS настроен корректно, это проверено 2026-08-03:
- apex `tetrishonot.com` → четыре A-записи GitHub Pages
  (`185.199.108-111.153`) ✅
- **AAAA-записи нет** — та самая паразитная запись на хостинг Timeweb, ломавшая сайт
  раньше, отсутствует ✅
- `www` → CNAME на `fildrummm-afk.github.io` ✅

**Диагноз:** страница тянула **20.7 МБ** изображений — фотографии были залиты
в оригинальном разрешении прямо с камеры и грузились целиком, хотя в галерее
показываются в несколько сотен пикселей.

| photo8.jpg | 4.4 МБ, 4558×6000 | 0.2 МБ, 1367×1800 |
| photo1.jpg | 4.3 МБ, 4156×4156 | 0.3 МБ, 1800×1800 |
| photo3/4/6/7 | по 2.0-2.4 МБ | по 0.2 МБ |
| logo.png | 592 КБ, 3000×3000 | 87 КБ, 800×800 |

**Как сделано:** ресайз до 1800px по длинной стороне (запас под retina-экраны),
JPEG качество 85, progressive, EXIF-ориентация сохранена. Оригиналы остались

**Проверено на проде** после деплоя (коммит `e0015b7`): суммарно 1.9 МБ,
главная отвечает за 0.44 с.

⚠️ **На будущее:** не заливать фото прямо с камеры. Перед добавлением в галерею
прогонять через ресайз до ~1800px. Иначе проблема вернётся с новой фотосессией.

### Не тронуто (на усмотрение владельца)

Репозиторий весит **179 МБ** из-за исходников, которые сайт не запрашивает:
`Tet Rishonot logo 1.psd` и `logo 4.psd` (6-7 МБ каждый), фотосессия `IMG_*.JPG`,
`обложка лицо.jpg`, `TET на экран.jpg`. На скорость сайта они **не влияют**, но делают
клонирование тяжёлым. Варианты, если захочется разгрузить: Git LFS или вынос исходников
в облачное хранилище.

## Известная проблема с DNS (следить)

В сессии Нейроцеха 2026-07-02/03 разбиралась поломка: в панели Timeweb появлялась
**паразитная AAAA-запись**, указывающая на хостинг Timeweb, хотя сайт живёт на
GitHub Pages. Панель Timeweb при манипуляциях с доменом склонна добавлять A/AAAA на себя.

**Лечение:** удалить лишнюю AAAA либо прописать четыре AAAA GitHub Pages
(`2606:50c0:8000::153`, `8001`, `8002`, `8003`). После любых операций с доменом
проверять `dig A/AAAA tetrishonot.com @ns1.timeweb.ru`.

Отдельно: имеет смысл включить **transfer lock** на домен.
