## ⚠️ История: просрочка сертификата, 08–13.08.2026

**Сбылось предупреждение из диагностики 03.08.** Сертификат истёк **08.08.2026**
и автоматически не перевыпустился. Сайт отдаёт `200`, но по `https://` браузер
показывает «Подключение не защищено».

### Что проверено живьём 13.08.2026

| Что | Результат | Чем проверено |
|---|---|---|
| Сертификат apex | истёк 08.08.2026, выпущен 10.05.2026, Let's Encrypt R13 | `openssl s_client` + `x509 -dates` |
| Сайт отвечает | да, код 200 | `curl -k` |
| A-записи apex | четыре адреса GitHub Pages ✅ | `dig A` и `dig A @ns1.timeweb.ru` |
| **Паразитная AAAA** | **отсутствует** ✅ | `dig AAAA` |
| **CAA-запись** | **отсутствует** — Let's Encrypt не заблокирован ✅ | `dig CAA` |
| `www` | CNAME на `fildrummm-afk.github.io`, резолвится в IPv6 GitHub ✅ | `dig CNAME/AAAA` |
| Состояние в GitHub Pages | `dns_changed` — «обнаружено изменение DNS, запрашиваю новый сертификат» | `gh api repos/.../pages` |
| Принудительный HTTPS | **выключен** (`https_enforced: false`) | там же |
| Покрытие сертификата | только `tetrishonot.com`, без `www` | там же |

**Вывод: DNS ни при чём.** Все записи корректны, в том числе те, на которых
проект обжигался раньше. Застряла сторона GitHub — состояние `dns_changed`
не сменилось за 10 дней и пережило истечение сертификата.

### Что сделано 13.08.2026

Через API GitHub Pages выполнена штатная процедура перевыпуска — отвязка
и обратная привязка домена:

```bash
gh api -X PUT repos/fildrummm-afk/tetrishonot-site/pages -F cname=null
gh api -X PUT repos/fildrummm-afk/tetrishonot-site/pages -f cname=tetrishonot.com
```

Домен привязан обратно, запрос сертификата принят. **Через 5 минут после
операции состояние оставалось `dns_changed`** — это нормально, GitHub заявляет
срок выпуска до 24 часов.

⚠️ **Честная оговорка.** Судя по коммитам `c301230 Delete CNAME` и
`672696b Create CNAME` от 03.08.2026, отвязка/привязка **уже предпринималась**
и результата не дала. Разница в том, что тогда, судя по виду коммитов,
правился сам файл `CNAME` через веб-редактор, а 13.08 выполнена именно
операция «убрать custom domain» над настройками Pages. Это не одно и то же,
но **гарантии нет**.

### Что делать дальше

1. Проверить состояние: `gh api repos/fildrummm-afk/tetrishonot-site/pages`
   — нужно `https_certificate.state: approved`.
2. Как только выпущен — **включить принудительный HTTPS**:
   ```bash
   gh api -X PUT repos/fildrummm-afk/tetrishonot-site/pages -F https_enforced=true
   ```
3. Проверить оба адреса: `https://tetrishonot.com` и `http://tetrishonot.com`
   (второй должен перебрасывать на https).
4. **Если через 24 часа состояние всё ещё `dns_changed`** — это уже дефект
   на стороне GitHub, чинить перепривязкой бесполезно. Обращаться в поддержку
   GitHub через https://support.github.com, тема — «Pages custom domain stuck
   in dns_changed, certificate expired», приложить, что DNS проверен и корректен.

## ⚠️ Диагностика 2026-08-03 (история)

**Причины две, обе чинятся в веб-интерфейсе GitHub**
(Settings → Pages репозитория `fildrummm-afk/tetrishonot-site`). Сервер и DNS ни при чём.

### Причина 1 — на `www` нет своего сертификата

`https://www.tetrishonot.com` отдаёт сертификат с именем **`*.github.io`** вместо
`www.tetrishonot.com`. Браузер видит, что имя в сертификате не совпадает с адресом,
и показывает предупреждение об угрозе. Редирект 301 на apex настроен и работает,
но TLS-рукопожатие происходит **раньше** редиректа — поэтому предупреждение успевает
выскочить.

```
apex:  subject= CN=tetrishonot.com     ← Let's Encrypt, всё верно
www:   subject= CN=*.github.io          ← ЧУЖОЕ ИМЯ, отсюда предупреждение
```

### Причина 2 — выключен «Enforce HTTPS»

`http://tetrishonot.com` отдаёт **200 вместо 301** — то есть по незашифрованному
протоколу сайт открывается как есть, без переброса на HTTPS. Chrome помечает такие
страницы как «Не защищено».

### Что сделать (веб-интерфейс, ~3 минуты)

1. GitHub → репозиторий `tetrishonot-site` → **Settings → Pages**.
2. В блоке **Custom domain**: нажать **Remove**, сохранить, затем вписать заново
   `tetrishonot.com` и сохранить. Это заставит GitHub перевыпустить сертификаты
   **сразу на оба имени** — apex и www.
3. Дождаться, пока пропадёт надпись про «certificate is being provisioned»
   (обычно 5-20 минут, иногда до часа).
4. Поставить галочку **Enforce HTTPS** — она становится доступной только после
   выпуска сертификата.
5. Проверить оба адреса: `https://www.tetrishonot.com` и `http://tetrishonot.com`
   (второй должен сам перебросить на https).

### Дополнительно: срок сертификата

Текущий сертификат apex выпущен **10.05.2026**, истекает **08.08.2026** — на момент
диагностики оставалось **5 дней**. GitHub Pages обновляет Let's Encrypt автоматически,
но раз перевыпуск всё равно требуется по причине 1, он заодно закроет и этот вопрос.
Если после 08.08 сайт начнёт ругаться на просроченный сертификат — причина здесь.

### Что проверять НЕ надо

DNS настроен корректно, это проверено 2026-08-03:
- apex `tetrishonot.com` → четыре A-записи GitHub Pages
  (`185.199.108-111.153`) ✅
- **AAAA-записи нет** — та самая паразитная запись на хостинг Timeweb, ломавшая сайт
  раньше, отсутствует ✅
- `www` → CNAME на `fildrummm-afk.github.io` ✅

## Известная проблема с DNS (следить)

В сессии Нейроцеха 2026-07-02/03 разбиралась поломка: в панели Timeweb появлялась
**паразитная AAAA-запись**, указывающая на хостинг Timeweb, хотя сайт живёт на
GitHub Pages. Панель Timeweb при манипуляциях с доменом склонна добавлять A/AAAA на себя.

**Лечение:** удалить лишнюю AAAA либо прописать четыре AAAA GitHub Pages
(`2606:50c0:8000::153`, `8001`, `8002`, `8003`). После любых операций с доменом
проверять `dig A/AAAA tetrishonot.com @ns1.timeweb.ru`.

Отдельно: имеет смысл включить **transfer lock** на домен.

## Приёмная — правки сайта через бота

Товарищ генерал присылает замечания по сайту личному боту «Приёмная» (отдельный
проект, живёт не здесь). Агент без своего окна правит копию сайта, присылает
снимки «было/стало», и товарищ генерал сам нажимает «Выложить» или «Откатить».

- **Договор** — файл `priyomnaya.yaml` в корне этого репозитория. В нём записано,
  что боту разрешено менять (`index.html` и новые картинки в `img/`), карта
  страницы словами владельца, порядок проверки и выкладки. Правка договора меняет
  поведение бота; удаление файла отключает сайт от Приёмной. **Договор правится
  из сессии в этой папке**, а не из проекта бота.
- Коммиты вида «Правка по замечанию владельца № N (Приёмная)» и откаты вида
  «Revert …» сделаны ботом по кнопке владельца, не агентом вручную. Не
  переписывать их без причины; откатить правку — кнопкой в боте либо обычной
  правкой здесь.
- Новые картинки, добавленные ботом, лежат в `img/` (уже ужатые под сайт).
- **У Приёмной нет доступа к этой папке** — у неё своя отдельная копия сайта,
  точка встречи — GitHub. Поэтому **перед началом работы здесь всегда
  `git pull --ff-only`**: бот мог выложить правку, пока в этой папке не работали.
